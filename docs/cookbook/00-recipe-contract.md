# Cookbook: how to use the recipes

**Evidence and limits:** As of 2026-11-11, CLI 1.0.109 has reported its version and help on Windows; one interactive `/plan` scenario reached a review dialog and shell-level `copilot init` created instructions in a synthetic repository. Four adapted prompts were exercised on synthetic data, with one requirements prompt failing its assumption-labeling check. The remaining recipes have not been executed end to end, and their scenario outcomes and model entitlements are not guaranteed. Each recipe supplies a reusable task, review boundary and acceptance check; validate it against your repository and policy before accepting a result. See [verification ledger V32–V36](../../reference/verification-ledger.md).

## Common prerequisites, model choice and setup

- Use a working, authenticated and policy-permitted Copilot CLI; the minimum supported version is **unverified**. Check the target CLI's help, mode, model access and permissions before use. Use a trusted, isolated checkout with the relevant source and safe test data. Preserve pre-existing changes and identify the task owner.
- Choose an organization-approved model available in the session. For a bounded inventory or straightforward diagnosis, start with a candidate evaluated as adequate for evidence gathering; for cross-service architecture or a difficult defect, use a candidate evaluated for complex reasoning. These are editorial heuristics, not verified model rankings. Record the selected model and settings; evaluate the result using [M3](../models/03-evaluation.md).
- Prompts below are **natural-language text for a Copilot session, not shell commands**. Replace bracketed terms with confirmed project details and omit secrets. Start `copilot` in the intended trusted workspace, review its active permission mode, and paste the selected prompt into the interactive prompt. The interactive `/plan` review and both initialization entry points were observed in limited Windows 1.0.109 fixtures; existing-file handling and other modes remain unverified. See [C2](../commands/02-initialization.md), [C3](../commands/03-plan-to-acceptance.md) and the [CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference).

## Common approval, validation and recovery

Initial prompts request investigation or a plan only. Inspect effective permissions and separately approve any file changes, test execution, dependency installation, network access, migration, cloud operation or external write. Prompts alone are not a security boundary. Select tests in the actual project's documented toolchain; no recipe asserts that a test was run. Verify cited source and the working tree, and record results and omissions. On unexpected action, stop, preserve evidence and unrelated work, assess the actual changes and use the organization's recovery process. For failed or unavailable tests, report the failure and do not claim acceptance.

Each entry identifies its **goal**, task-specific **setup**, **prompt**, expected **result and acceptance** and **failure/recovery**. The shared prerequisites, model rationale, approval boundary and source evidence above are part of every entry.
