Configuration Settings:

  Change these settings with `copilot config`, using dot notation for nested keys:
    $ copilot config footer.showQuota off
    $ copilot config allowedUrls github.com         # adds an item to a list setting
    $ copilot config allowedUrls
    $ copilot config --rm allowedUrls github.com    # removes one item from a list setting
    $ copilot config --list
  Use --repo or --local to change .github/copilot/settings.json or settings.local.json.

  `allowedUrls`: list of URLs or domains that are allowed to be accessed without prompting.
    Supports exact URLs (e.g., "https://github.com"), domain patterns (e.g., "github.com"),
    and wildcard subdomains (e.g., "*.github.com").

  `autoUpdate`: whether to automatically download updated CLI versions, and to update plugins from auto-updating marketplaces when a session starts; defaults to `true`, or `false` in CI environments.
    Plugin updates cover the built-in awesome-copilot marketplace and any `extraKnownMarketplaces` entry
    with `"autoUpdate": true` in your user settings or your organization's managed settings (repository settings do not count).
    On standalone-binary installations, downloads run in the background and a downloaded
    version applies at your next launch of the CLI, unless that launch opts out with
    `--no-auto-update` or `COPILOT_AUTO_UPDATE=false`; `/restart`
    applies it in the CLI you already have open. Setting this to `false` only stops
    further downloads - it does not stop an already downloaded version from applying.
    Installations run from npm/JavaScript only report that a newer version is available -
    installing it stays a manual `npm install`.

  `banner`: frequency of showing animated banner; defaults to "once".
    - "always" displays it every time
    - "never" disables it
    - "once" displays it the first time

  `bannerStyle`: which artwork the startup banner uses; defaults to "mona".
    - "mona" is the two-Mona pixel-art hi-five
    - "classic" is the COPILOT wordmark with the goggled mascot
    - Ignored when `banner` resolves to "never"

  `bashEnv`: whether to enable BASH_ENV support for bash shells; defaults to `false`.
    - Can also be set with --bash-env or --no-bash-env
    - Using either flag persists the preference to config

  `beep`: whether to beep when user attention is required; defaults to `false`.

  `beepOnSchedule`: whether to beep when a scheduled `/every` (or `/after`) run finishes; defaults to `true`.
    - Only applies when `beep` is enabled; set to `false` to silence completion beeps for scheduled runs.

  `notifications`: whether to show OS notifications when user attention is required and when the agent finishes; defaults to `false`.
    - Set to `true` to enable desktop toasts. Toasts are suppressed while the terminal window already has focus.
    - Clicking a toast attempts to focus the terminal window that raised it where supported; multi-tab terminals (e.g. Windows Terminal) can't switch to the specific tab.

  `terminalNotifications`: whether to prefer terminal-owned OSC 777 notifications; defaults to `false`.
    - Requires `notifications` to be enabled.
    - Used for recognized, active Ghostty and WezTerm sessions. Herdr uses its own notification path; tmux, GNU screen, Zellij, unsupported terminals, and rejected writes try the OS notification backend when available.

  `powershellFlags`: list of flags passed to PowerShell (pwsh) on startup; defaults to `["-NoProfile", "-NoLogo"]`.
    - Overrides the default flags when set; only applies on Windows
    - Examples: `["-NoProfile"]` to keep the logo, `[]` to load your profile and show the logo,
      `["-NoProfile", "-NoLogo", "-ExecutionPolicy", "Bypass"]` for locked-down environments
    - Use caution: flags that change execution semantics (`-Command`, `-File`, `-NoExit`,
      `-NonInteractive`, `-EncodedCommand`, `-InputFormat`, `-OutputFormat`) will break
      the runtime. See the settings documentation for details.

  `compactPaste`: whether to collapse large pasted content into compact tokens; defaults to `true`.
    - When `true` (default), pastes with more than 10 lines are displayed as `[Paste #N - X lines]`
    - When `false`, pasted content is displayed directly in the input
    - Either way, a paste larger than 20.0 KB is saved to a file in the session workspace and displayed as `[Saved pasted content to workspace (<size>) id=N]`

  `copyOnSelect`: whether selecting text in alt screen mode automatically copies it to the system clipboard; defaults to `true` on macOS, `false` elsewhere.
    - When `true`, text is copied to the system clipboard as soon as the mouse button is released after a selection
    - When `false` (the default except on macOS), use Ctrl+C or right-click to copy selected text to the system clipboard
    - On Linux, the X11 primary selection is always updated on selection regardless of this setting

  `commandHistoryMaxSize`: maximum number of recent prompts kept for Ctrl+R command-history search and up/down history navigation; defaults to `50`.
    - History is newest-first and deduplicated; entries beyond this many are dropped
    - Must be an integer between `1` and `1000`; out-of-range or invalid values fall back to `50`
    - Lowering it trims the in-memory history immediately and persists on the next submitted prompt

  `customAgents.defaultLocalOnly`: whether to default to only use local custom agents (no remote org/enterprise); defaults to `false`.

  `deniedUrls`: list of URLs or domains that are denied access. Denial rules take precedence
    over allow rules.

  `proxyKerberosServicePrincipal`: service principal name (SPN) for Kerberos/Negotiate proxy
    authentication; overrides the derived `HTTP/<proxy-host>`. Mirrors VS Code's
    `http.proxyKerberosServicePrincipal`.
    - The `COPILOT_PROXY_KERBEROS_SPN` environment variable, when set, takes precedence
    - Changing this requires a restart to take effect

  `proxyUrl`: proxy URL for HTTP(S) requests (e.g. `http://proxy.corp.example:3128`).
    - Can be overridden by the `HTTP_PROXY` / `HTTPS_PROXY` environment variables (any casing,
      including lowercase `http_proxy` / `https_proxy`); if either is set in the environment,
      it takes precedence and this setting is ignored
    - `NO_PROXY` from the environment is still honored
    - Changing this requires a restart to take effect

  `experimental`: whether to enable experimental features; defaults to `false`.
    - Can be enabled with --experimental flag, /settings experimental on, or /experimental (deprecated)

  `memory`: whether to enable agentic memory (cross-session fact recall); defaults to `true`.
    - Toggle with `/memory on|off` (writes this setting)
    - When `false`, the agent will not store or recall memories
    - Non-interactive `-p` runs start with memory off regardless of this setting; pass `--enable-memory` to turn it on
    - Repository memories are kept on GitHub for everyone using Copilot Memory in that repository; view or delete them in its Settings > Copilot > Memory, and your own at https://github.com/settings/copilot/memory

  `includeCoAuthoredBy`: whether to instruct the agent and its subagents to add a Co-authored-by trailer to git commits; defaults to `true`.

  `keepAlive`: keep-alive mode applied at CLI startup; prevents the system from sleeping while the session is active. Defaults to `"off"`.
    - `"off"` (default): system sleeps normally.
    - `"on"`: keep-alive is enabled for the duration of the session.
    - `"busy"`: keep-alive is enabled only while the agent is working on a turn.
    - `/keep-alive [on|off|busy|<duration>]` changes keep-alive for the current session only; it does not change this setting.

  `companyAnnouncements`: list of messages to display in the banner on startup.
    - One message is randomly selected each time the CLI starts
    - Useful for team announcements or reminders

  `continueOnAutoMode`: whether to automatically switch to auto mode when rate-limited; defaults to `false`.
    - When `true`, eligible rate limit errors (per-model, weekly, or integration limits) trigger an automatic switch to auto mode and retry
    - Does not apply to global rate limits, generic 429s, or BYOK providers

  `stayInAutopilot`: whether to stay in autopilot mode after an autopilot task completes; defaults to `true`.
    - When `true` (default), the CLI remains in autopilot mode after the agent calls `task_complete` instead of exiting to interactive mode
    - Set to `false` to revert to interactive mode after each completed task

  `defaultMode`: agent mode new interactive sessions start in; defaults to "interactive".
    - One of "interactive", "plan", or "autopilot"
    - `--mode`, `--autopilot`, and `--plan` still win when passed
    - Resumed sessions keep their own persisted mode, and it does not apply to `-p`/`--prompt`, SDK server, or `--acp` runs

  `defaultPermissionMode`: permission mode new interactive sessions start in; defaults to "manual" unless an eligible organization targets Assisted.
    - `"manual"` (default): write and command requests are prompted; read-only requests are auto-approved
    - `"assisted"`: a probabilistic LLM review reduces confirmation dialogs by auto-approving requests it judges safe and asking otherwise; it is not a security boundary and may approve dangerous or unintended actions, so use managed restrictions, sandboxing, least-privilege credentials, and egress controls for enforceable protection
    - `"allow-all"`: auto-approves everything, equivalent to launching with `--allow-all`; ignored when policy disables bypass-permissions mode
    - Any value is ignored on resumed sessions, outside interactive runs, and when `--allow-all`/`--yolo` already elevated the session
    - Pairs with `defaultMode: "autopilot"` to skip the autopilot permission confirmation entirely

  `logLevel`: log level for CLI; defaults to "default". Set to "all" for debug logging.
    - Change it in the /settings dialog or by editing settings.json; `copilot config` and `/settings logLevel <value>` do not accept it
    - For one run, pass --log-level

  `model`: AI model to use for Copilot CLI, including custom and local models; can be changed with /model command or --model flag option. Refer to `copilot help providers`.
    - "claude-sonnet-5.5"
    - "claude-sonnet-5"
    - "claude-fable-5.2"
    - "claude-fable-5.1"
    - "claude-fable-5"
    - "claude-opus-5.5"
    - "claude-opus-5"
    - "claude-opus-4.8"
    - "claude-opus-4.8-fast"
    - "claude-sonnet-4.6"
    - "claude-haiku-5.5"
    - "claude-haiku-4.5"
    - "gpt-6.1-sol"
    - "gpt-6.1-terra"
    - "gpt-6-sol"
    - "gpt-6-luna"
    - "gpt-6-astra"
    - "gpt-5.6-sol"
    - "gpt-5.6-terra"
    - "gpt-5.6-luna"
    - "gpt-5.3-codex"
    - "mai-code-1.1-flash"
    - "gemini-4-argon"
    - "gemini-3.8-flash"
    - "grok-4.7"
    - "grok-4.6"
    - "kimi-k3"

  `contextTier`: context window tier for tiered-pricing models (e.g., "default" or "long_context").
    - Can also be set with --context flag (overrides persisted setting)
    - Can be changed with /model command (context tier picker appears for eligible models)

  `autoTier`: routing profile used when the selected model is Auto (displayed as Copilot Fusion in local sessions). Normally "efficiency", "balance", or "intelligence"; server-advertised profiles are also accepted in local sessions. The CLI and SDK accept `fusion` as the model name; stored model IDs remain `auto`. A stored "fast" profile is still read, for compatibility with other Copilot clients and with settings older CLI versions wrote, but the CLI cannot run on it and uses "balance" instead.
    - Can also be set with --auto-tier (overrides the persisted setting)
    - Configured interactively with /config model when Auto preferences are available

  `fusionTier`: Copilot Fusion tier used when the selected model is Auto: "standard", "high", or "max".
    - Set with `copilot config fusionTier <tier>`; a managed organization setting may override it

  `subagents.agents.<agent-name>`: per-subagent model, effortLevel, and contextTier selection.
    - Each field can be set to "inherit" to use the parent session's effective value
    - Configure interactively with the /subagents command

  Session limits are opt-in. They apply across the current conversation; /clear and /new reset used AI credits but keep the configured limit until you unset it.
    - Run /limits with no arguments to open the interactive limits dialog
    - Use /limits set max-ai-credits <credits> to set the AI credit limit
    - Use --max-ai-credits to set an initial AI credit limit when starting the session
    - The minimum AI credit limit is 30; lower values are too small for a useful CLI turn
    - AI credit usage is known only after a model call returns, so one call can exceed the limit before the CLI blocks
      the next model call

  `mouse`: whether to enable mouse support in alt screen mode; defaults to `true`.
    - Can also be set with --mouse or --no-mouse
    - Using either flag persists the preference to config
    - When disabled, scroll wheel and click events are not captured by the CLI

  `renderMarkdown`: whether to render markdown in the terminal; defaults to `true`.

  `inlineImages`: whether to render images inline using the Kitty graphics protocol (or Sixel graphics); defaults to `true`.
    - Only takes effect on terminals that support Kitty graphics (e.g. Ghostty, kitty, WezTerm), and inside tmux with passthrough enabled
    - In a herdr pane, herdr draws the images itself rather than passing them through, which requires `experimental.kitty_graphics = true` in herdr's own config (off by default upstream). The CLI detects that automatically over herdr's socket API; no opt-in is needed. If the probe cannot answer (e.g. an older herdr server or an inaccessible socket), set `COPILOT_INLINE_IMAGES_HERDR=1` only after enabling herdr's renderer to force inline rendering; `=0` forces text, and unset uses automatic detection. Forcing rendering without herdr's renderer produces broken placeholder cells. The override does not bypass GNU screen, the feature flag, screen reader mode, or `inlineImages: false`
    - With the experimental `INLINE_IMAGES_SIXEL` feature also enabled, images render with Sixel graphics in terminals without Kitty graphics that report Sixel support and whose cell size the CLI can measure (from the pty's pixel size, else the terminal's text area size), such as Windows Terminal 1.22 or later. Sixel stays off inside terminal multiplexers. Images can draw with defects in xterm, VTE-based terminals (e.g. GNOME Terminal) and Konsole; set `INLINE_IMAGES_SIXEL=false` to turn Sixel off
    - In screen reader mode, images show their text caption instead
    - When disabled, image attachments show a text placeholder instead

  `inlineImageLiveWindow`: maximum number of inline images kept resident in the terminal at once (the most-recent N by timeline order); defaults to `50`.
    - Images beyond N render as a text caption and have their data freed from the terminal, bounding its image memory in long, image-heavy sessions
    - Set to `0` to disable the cap (keep every inline image resident)
    - The `COPILOT_INLINE_IMAGE_LIMIT` environment variable overrides this setting

  `scrollbar`: whether to show the scrollbar in scrollable views; defaults to `true`.
    - When `false`, the scrollbar is hidden and its gutter is reclaimed so content uses the full terminal width.

  `respectGitignore`: whether to exclude gitignored files from the `@` file mention picker; defaults to `true`.
    - When `false`, the `@` picker includes files that are normally excluded by `.gitignore`
    - Useful when sub-repositories or vendor directories are gitignored but still need to be referenced

  `screenReader`: whether to enable screen reader optimizations; defaults to `false`.

  `stream`: whether to enable streaming mode; defaults to `true`.

  `statusLine`: configuration for a custom status line displayed below the input.
    - `type`: optional; when set, must be "command"
    - `command`: path to an executable script or a shell command that generates status line content.
      Supports `~` (home directory) and environment variables (`$HOME`, `${HOME}`, `${VAR:-default}`).
      Plain commands are run with the platform shell (`/bin/sh` on Unix-like systems, `cmd.exe` on Windows).
      The command receives the current session status as JSON on stdin and should print the status line to stdout.
    - `padding`: optional number of spaces to pad each line on the left
    - `refreshInterval`: optional integer number of seconds between command re-runs (minimum `1`, maximum `2147483`); omit to refresh only on events

  `tabs`: configuration for the home screen navigation tab bar (Current, Sessions, Issues, Pull requests, Gists).
    - `enabled`: whether to show the tab bar; defaults to `true`. Set to `false` to hide it entirely.
    - `sort`: array of tab identifiers controlling display order. Accepted identifiers (case-insensitive): `copilot` (Current), `agents` (Sessions), `issues`, `pull-requests`, `gists`. Tabs not listed keep their default order after the listed ones; unknown identifiers are ignored.
    - `hide`: array of tab identifiers to hide (same identifiers as `sort`). Unknown identifiers are ignored; the `copilot` (Current) tab cannot be hidden.

  `terminalProgress`: whether to emit terminal progress indicators (OSC 9;4) while the agent is working; defaults to `true`.
    - Shows an indeterminate progress indicator in the terminal title bar or tab on supported emulators (Windows Terminal, iTerm2, Ghostty, ConEmu)
    - Set to `false` to suppress these escape sequences on terminals that render them as visible artifacts

  `theme`: color palette / theme for output; defaults to "github".
    - One of: "default", "github", "dim", "high-contrast", "colorblind"
    - Set via /settings theme <value>, or /theme <value> (deprecated)
    - `colorMode` is a legacy alias for `theme` and still works for now

  `trustedFolders`: folders you have trusted, so the CLI does not ask again before working in them.
    - Stored in config.json in the Copilot home directory, not in settings.json, so `copilot config` cannot change it
    - A folder is added when you choose "Yes, and remember this folder for future sessions" at the folder-trust prompt

  `updateTerminalTitle`: whether to update the terminal tab/window title with current intent; defaults to `true`.
    - Shows what the agent is currently working on in the terminal title bar
    - Only works on supported terminal emulators (xterm, iTerm, Windows Terminal, etc.)
    - Can also be disabled via the `COPILOT_DISABLE_TERMINAL_TITLE` environment variable

  `disableAllHooks`: whether to disable all hooks (repo-level and user-level); defaults to `false`.

  `hooks`: inline hook definitions, keyed by event name (same schema as .github/hooks/*.json).
    - In the user settings.json these act as user-level hooks; in repo settings.json they act as repo-level hooks

  `ide.autoConnect`: whether to automatically connect to an IDE workspace on startup; defaults to `true`.
    - When `false`, the CLI will not auto-connect to IDEs or watch for new IDE lock files
    - You can still manually connect using the /ide command

  `ide.openDiffOnEdit`: whether to open file edit diffs in the connected IDE for approval; defaults to `true`.
    - When `false`, file edit approvals are shown only in the terminal
    - The IDE connection is unaffected; diagnostics and selection features still work

  More settings, described by the settings catalog that `copilot config --list` and /settings read.
    Some only take effect when the feature they belong to is available to you.

  `askUser`: Let the agent ask clarifying questions through the ask_user question form. When off, it
    can still ask in its replies.
  `autoUpdatesChannel`: Update channel: stable or prerelease.
  `copyOnCodeBlockClick`: Click a code block in a completed response to copy its code. Requires
    mouse support. Defaults to off.
  `worktreeBaseRef`: Ref used as the starting point for new clean worktrees. Use head for the
    current checkout or defaultBranch for the remote default branch. A rollout feature flag may
    change the default when unset.
  `worktreePathTemplate`: Where new worktrees are created, e.g. ~/src/worktrees/{repo}/{branch}.
    Fields: {repoPath} repository path, {repo} its directory name, {branch} branch name (slashes
    nest), {branchSlug} branch name with slashes as dashes. Unset: <repo>.worktrees/<branchSlug>.
  `imageGeneration`: Allow the agent to generate and edit images when image generation is available.
    Defaults to true; set to false to turn it off. Takes effect in new sessions.
  `imageGenerationWatermark`: Request a visible Made with AI label on generated and edited images.
    Defaults to false. Does not enable image generation or enforce enterprise policy.
  `toolSearch`: Enable tool search with deferred tool loading.
  `contextManagementTools`: Allow the agent to use the context management tools: session_artifacts,
    get_context_remaining, session_history, and new_context.
  `sessionManagementTools.enabled`: Enable local peer access through list, create, message, close
    and rename tools. Off by default.
  `sessionManagementTools.scope`: Limit discovery and direct peer access to all opted-in local
    sessions sharing this configuration directory (default), or only sessions hosted in this runtime
    process. In-process sessions are not exposed to other processes. Does not include remote
    sessions or Mission Control.
  `sessionManagementTools.list`: Allow list_sessions to discover other opted-in sessions.
  `sessionManagementTools.create`: Allow create_session to start a separate session with inherited
    launch options or explicit overrides.
  `sessionManagementTools.message`: Allow send_session_message to deliver peer text to another
    opted-in session.
  `sessionManagementTools.close`: Allow close_session to close sessions created by this session or
    its descendants without deleting history. Enabled by default with session management; can be
    disabled individually.
  `modelProviderId`: Provider owning the selected model. Paired with model to distinguish catalogs
    that serve the same model identifier.
  `effortLevel`: Reasoning effort for models that support it: none, minimal, low, medium, high,
    xhigh or max. Which levels a model offers depends on the model; in the /model picker, left and
    right arrows step through the highlighted model's levels. When unset, the model's own default is
    used, which is medium for most models.
  `planModel`: AI model to use for plan mode. Falls back to the session model when unset.
  `planModelProviderId`: Provider owning planModel. Omit for legacy model selection.
  `planEffortLevel`: Reasoning effort for plan mode on models that support it. When unset, the plan
    model's own default effort is used (the session effort is not inherited).
  `planContextTier`: Context tier for plan mode on models that support tiered context windows. When
    unset, the plan model's own default tier is used (the session tier is not inherited).
  `subagents.disabledSubagents`: Subagents discovered but disabled from delegation.
  `subagents.maxConcurrency`: Maximum number of subagents that can run concurrently. Ignored on
    Copilot plans without usage-based billing.
  `subagents.maxDepth`: Maximum subagent nesting depth. Ignored on Copilot plans without usage-based
    billing.
  `subagents.contextManagementTools`: Allow subagents to use the context management tools:
    session_artifacts, get_context_remaining, session_history, and new_context.
  `workflows.maxConcurrentRuns`: Maximum number of top-level workflow runs that can run
    concurrently. Default: 4. Range: 1-16. Dynamic workflows need experimental mode and either
    usage-based billing or a custom model provider (BYOK) while signed out of GitHub.
  `workflows.logPhaseNames`: Emit workflow phase names to the session transcript. Default: true.
    Dynamic workflows need experimental mode and either usage-based billing or a custom model
    provider (BYOK) while signed out of GitHub.
  `workflows.defaultLimits.maxConcurrentSubagents`: Fallback maximum number of concurrently active
    subagents per workflow run. Workflow declarations and per-run overrides take precedence. If
    unset, maxTotalSubagents supplies the bound or concurrency is unlimited. Values above 4096 are
    clamped to 4096. Dynamic workflows need experimental mode and either usage-based billing or a
    custom model provider (BYOK) while signed out of GitHub.
  `workflows.defaultLimits.maxTotalSubagents`: Fallback maximum number of subagents created over a
    workflow run's lifetime. Workflow declarations and per-run overrides take precedence. If every
    source is unset, the total is unlimited. Range: positive integer through 4294967295. Dynamic
    workflows need experimental mode and either usage-based billing or a custom model provider
    (BYOK) while signed out of GitHub.
  `workflows.defaultLimits.timeoutSeconds`: Fallback active-time limit in seconds for a workflow
    run. Workflow declarations and per-run overrides take precedence. If every source is unset,
    active time is unlimited. Range: greater than 0 through 2147483.647. Dynamic workflows need
    experimental mode and either usage-based billing or a custom model provider (BYOK) while signed
    out of GitHub.
  `workflows.defaultLimits.maxAiCredits`: Fallback soft post-paid AI-credit ceiling for a workflow
    run. Workflow declarations and per-run overrides take precedence. If every source is unset, AI
    credits are unlimited. The value must round to a safe positive integer nano-AIU ceiling. Dynamic
    workflows need experimental mode and either usage-based billing or a custom model provider
    (BYOK) while signed out of GitHub.
  `assistedApprovalInstructions`: Your custom instructions for the Assisted Permissions judge,
    separate from agent instructions. Applies to local sessions; changing it does not enable
    Assisted Permissions or change permission mode. Blank clears. Repository settings cannot supply
    this value.
  `shellShortcut`: Type a lone $ at the prompt, then press enter, to open an interactive shell in
    the session directory. Local, trusted sessions only; on by default.
  `renderHexColors`: Render standalone six-digit hex color codes (e.g. #FF0000), including those in
    inline code, as color swatches.
  `pinnedPrompts`: Pin the current prompt below the top bar while scrolling the timeline, so it
    stays clear which request the output belongs to. Off by default.
  `sidebar.enabled`: Show the Sessions sidebar and allow opening it from the composer with the Left
    arrow.
  `sidebar.showResumableSessions`: Restore the launch directory's remembered sessions in the sidebar
    so a relaunch shows them without resuming manually.
  `sidebar.showHeaderButtons`: Show the sidebar's header button row (collapse sidebar, new session)
    above the session cards.
  `sidebar.showCloseButton`: Show a close button on each sidebar session card: hovering its right
    end reveals a red close region, and clicking arms then confirms closing that session.
  `sidebar.hoverFocus`: Follow the mouse in the split view: moving the pointer across the split
    divider focuses the pane it lands in, and sidebar cards and header buttons preview a hover
    highlight. Focus tracks divider crossings, not the pointer's resting side, so a keyboard or
    click focus change sticks until the mouse travels to the other pane. When off, nothing lights up
    on hover; clicks still work.
  `sidebar.coloredHints`: Color the composer's use sidebar hint with the sidebar's accent as a
    call-to-action while the split is open with the timeline focused. When off, it renders in the
    neutral hint color like every other shortcut. The open sidebar hint shown while the split is
    closed is always neutral.
  `sidebar.accentActiveSession`: Swap the sidebar card highlights: the active session card gets the
    pronounced accent fill (in both focus states) and the keyboard cursor gets the subtle one. When
    off, the cursor is accented and the active card is subtle.
  `sidebar.exitClosesSession`: When the Sessions sidebar is open and another session is still live,
    make /exit and /quit close only the current session instead of quitting the whole CLI; on the
    last remaining session, with the sidebar closed, or for the /exit print and /quit print
    variants, the whole CLI still exits.
  `sidebar.ctrlCClosesSession`: When the Sessions sidebar is open and another session is still live,
    make the confirming second Ctrl+C on an idle empty prompt close only the current session instead
    of quitting the whole CLI; on the last remaining session, or with the sidebar closed, it still
    quits the CLI. The first Ctrl+C only arms the confirmation, and Ctrl+C keeps cancelling an
    in-progress operation first.
  `remoteExport`: Export sessions to GitHub.
  `storeTokenPlaintext`: Store auth token in plaintext (less secure).
  `footer.showModelEffort`: Show the reasoning effort level next to the model name in the footer;
    the model name always shows. When unset, the effort shows for a few seconds after it changes.
  `footer.showDirectory`: Show the current directory in the footer.
  `footer.showBranch`: Show the current git branch in the footer.
  `footer.showContextWindow`: Show context-window usage in the footer.
  `footer.showQuota`: Show quota usage in the footer.
  `footer.showAiUsed`: Show the AI-used indicator in the footer.
  `footer.showAgent`: Show the active agent in the footer.
  `footer.showCodeChanges`: Show pending code changes in the footer.
  `footer.showUsername`: Show the username in the footer.
  `footer.showSandbox`: Show sandbox status in the footer.
  `footer.showYolo`: Show YOLO (allow all) status in the footer.
  `footer.showCiStatus`: Show CI/workflow check status for the current branch's PR in the footer.
  `footer.showSchedules`: Show the count of active scheduled prompts (/every, /after) in the footer.
  `footer.showPullRequest`: Show the current branch's pull request link in the footer.
  `footer.showCustom`: Show your custom status line, the output of `statusLine.command`, in the
    footer. On by default; `/statusline` toggles it as the `custom` item, and while it is off the
    command does not run.
  `mergeStrategy`: How /pr fix conflicts, /pr fix all, /pr auto and /pr agentmerge bring the base
    branch into your pull request branch: rebase rebases onto it and force-pushes with
    --force-with-lease; merge merges it in and pushes a merge commit. When unset, /pr fix conflicts
    and /pr fix all ask each time and can save your choice here, and /pr auto and /pr agentmerge let
    the agent choose. Repository settings can set it for one repository.
  `editorMode`: Composer editing mode (normal or vim keybindings).
  `ide.codeProduct`: Default VS Code product for /code when no matching VS Code window is running.
  `skillDirectories`: Additional custom directories for skills.
  `ignoredSkillsLocations`: Skill directories excluded from discovery.
  `disabledSkills`: Names of skills to turn off, so the agent cannot use them and they get no slash
    command. `/skills` and `copilot skill disable <name>` add a name and `copilot skill enable
    <name>` removes it; names match in any letter case, and a plugin's skill can be written
    `plugin:skill`. A trusted repository's `.github/copilot/settings.json` can add names too, and a
    skill named in either list stays off.
  `disabledHooks`: Hooks discovered but not executed (content-hash keys). Policy hooks cannot be
    suppressed and ignore this setting.
  `disabledMcpServers`: MCP servers configured but not started.
  `enabledMcpServers`: Built-in MCP servers explicitly enabled.
  `githubMcpToolsets`: GitHub MCP toolsets to enable beyond the default CLI subset (e.g.
    "projects"). Use "all" for every toolset.
  `githubMcpTools`: Individual GitHub MCP tools to request. Replaces the default CLI tool list
    rather than extending it; combine with githubMcpToolsets to also enable whole toolsets. Use "*"
    for all tools.
  `enableAllGithubMcpTools`: Enable all GitHub MCP server tools instead of the default CLI subset.
  `githubMcpInsiders`: Use the GitHub MCP server insiders build.
  `dynamicRetrieval.skills`: Enable embeddings-based retrieval of skills.
  `sandbox.enabled`: Enable tool sandboxing.
  `sandbox.userPolicy.filesystem.readwritePaths`: Absolute paths sandboxed commands can read from
    and write to.
  `sandbox.userPolicy.filesystem.readonlyPaths`: Absolute paths sandboxed commands can read but not
    write to.
  `sandbox.userPolicy.filesystem.enumeratePaths`: Windows only: absolute directories sandboxed
    commands can list and query attributes of, without reading file contents (for example a drive
    root like C:\). Ignored, with a log, on Windows builds without filesystem enumeration support
    and on other platforms.
  `sandbox.userPolicy.filesystem.deniedPaths`: Absolute paths sandboxed commands are denied access
    to, even if nested under a read/write or read-only path.
  `sandbox.userPolicy.network.allowOutbound`: Allow the sandboxed process to reach other hosts,
    including private networks.
  `sandbox.userPolicy.network.allowLocalNetwork`: Allow connections to this machine's loopback
    interfaces. Covers loopback access through proxies and MCP servers.
  `sandbox.userPolicy.network.allowedHosts`: Hosts allowed through the built-in local proxy. A
    non-empty list blocks unmatched hosts. Use exact hostnames, IP addresses, or *.example.com for
    strict subdomains. Deny rules take precedence.
  `sandbox.userPolicy.network.blockedHosts`: Hosts denied by the built-in local proxy, even if an
    allow rule matches. A domain also denies all its subdomains. IP addresses match exactly;
    *.example.com matches strict subdomains, and * matches every host.
  `sandbox.userPolicy.network.proxy.url`: HTTP(S) proxy for sandboxed traffic (e.g.
    http://proxy.example.com:8080). The built-in local proxy forwards sandboxed traffic to this
    endpoint as its upstream and applies any host rules, so proxy credentials never reach child
    processes. Configure authentication in the separate username/password fields.
  `sandbox.userPolicy.network.proxy.username`: Optional username for sandbox proxy authentication,
    combined with the URL and password into user:pass@host at spawn time.
  `sandbox.userPolicy.network.proxy.password`: Optional password for sandbox proxy authentication.
    Masked in the /sandbox dialog and redacted by /settings show; managed via /sandbox → Network or
    by editing settings.json directly.
  `sandbox.userPolicy.seatbelt.keychainAccess`: Let sandboxed commands use the macOS Keychain.
  `sandbox.addCurrentWorkingDirectory`: Auto-add the CWD to sandbox readwrite paths.
  `sandbox.sandboxMcpServers`: Spawn MCP servers inside the sandbox when enabled.
  `sandbox.sandboxLspServers`: Spawn LSP servers inside the sandbox when enabled.
  `sandbox.sandboxExtensions`: Spawn extension processes inside the sandbox when enabled. Defaults
    to true.
  `sandbox.allowBypass`: Allow the model to request a sandbox bypass for individual commands.
  `sandbox.auth.git`: When sandboxing is enabled, give sandboxed git a masked credential as an
    http.extraheader so authenticated HTTPS git works without the credential helper the sandbox
    blocks: the GitHub token for GitHub, and the answer from your own git credential helper for
    other hosts. The sandbox proxy substitutes the real credential only for requests to that HTTPS
    origin, so the command never sees it.
  `sandbox.auth.gh`: When sandboxing is enabled, export GH_TOKEN and redirect GH_CONFIG_DIR to an
    isolated temp dir so the gh CLI authenticates without the OS keyring the sandbox blocks.
  `sandbox.credentials.envVars`: Environment variables masked in sandboxed commands, keyed by their
    exact name. Each injectHosts list names the HTTPS destinations where the proxy may restore the
    value.
  `sandbox.allowDevToolAccess`: When sandboxing is enabled, auto-grant read access to tool
    directories discovered on PATH and in toolchain environment variables (GOROOT, JAVA_HOME,
    VIRTUAL_ENV, and similar), and to common developer-tool caches, config, and toolchains. Writable
    grants cover scratch caches, the Unix GitHub CLI cache, and Cargo's registry, git store, and
    lock/tracker files. A relocated CARGO_HOME gets the same narrow split: registry and git are
    read-write; bin is read-only; the home root, config.toml, and credentials.toml stay ungranted.
    Enabled by default. Set to false to disable every grant listed above; user-installed toolchains
    and caches then need explicit sandbox.userPolicy.filesystem readonlyPaths and readwritePaths
    entries. The working directory (see sandbox.addCurrentWorkingDirectory), temporary storage,
    session log paths, and system locations follow their own rules and stay granted.
  `extensions.disabledExtensions`: Extensions discovered but disabled.
  `extensions.mode`: Extension loading mode (disabled, load_only, load_and_augment).
  `enabledPlugins`: Plugins to turn on or off, keyed `name@marketplace`; `false` turns one off
    without uninstalling it. In a repository's `.github/copilot/settings.json` it shares plugins
    with everyone on the project: when they trust the folder, the plugins are installed if missing
    and turned on in that repository, not in their other projects. Put a marketplace that is not
    built in into the same file's `extraKnownMarketplaces`.
  `strictKnownMarketplaces`: Allowlist restricting which plugin marketplace sources may be installed
    (governance-managed).
  `telemetry.capture.identity`: Include the authenticated Copilot account, local operating-system
    account, and machine name as OpenTelemetry user.name, process.user.name, and host.name. These
    identifying values are off by default.
  `telemetry.capture.prompts`: Include prompt and other model-input content in OpenTelemetry.
  `telemetry.capture.responses`: Include assistant response and reasoning content in OpenTelemetry.
  `telemetry.capture.toolArguments`: Include raw tool arguments, definitions, and identifying tool
    metadata in OpenTelemetry.
  `telemetry.capture.toolOutput`: Include tool results and execution error details in OpenTelemetry.
  `telemetry.capture.policyDetail`: Include expanded sandbox filesystem policy paths and comparable
    unbounded policy details in OpenTelemetry.
  `telemetry.captureContent`: Legacy shorthand that enables all five OpenTelemetry content classes,
    but never user.name, process.user.name, or host.name.
  `telemetry.headersProvider`: Optional shell-free command that refreshes OpenTelemetry exporter
    headers. Set false to explicitly disable it.
  `voice.enabled`: Voice mode: dictate prompts with your microphone instead of typing, transcribed
    on your machine by a downloaded speech model. `/voice on` and `/voice off` save this, so voice
    mode comes back at the next launch (it is turned off if it then fails to start). Available on
    Windows x64 and arm64, Linux x64 and macOS on Apple silicon.
  `voice.selectedModel`: Speech-to-text model used for voice input.
  `voice.selectedDevice.name`: Preferred microphone device name (managed by /voice devices).
  `voice.selectedDevice.occurrence`: Disambiguates duplicate device names (0-based; managed by
    /voice devices).
  `permissions.disableBypassPermissionsMode`: Set to "disable" to turn off bypass-all-permissions
    (YOLO) mode.
  `showReasoning`: Show the model's reasoning summaries in the timeline (toggle with ctrl+t).
  `showTimestamps`: Show the time (HH:mm) next to each message you send in the timeline. Only your
    messages get a timestamp; assistant replies and tool calls do not.
  `showToolDurations`: Show how long each tool call took (for calls at least 5s) inline on the
    timeline.

Files and directories:

  Copilot CLI keeps its files in `$COPILOT_HOME`, which defaults to `~/.copilot`:
    - `settings.json`: your user settings (the settings above).
      Repository settings are in `.github/copilot/settings.json` and `.github/copilot/settings.local.json`.
      Hooks, `disableAllHooks`, `enabledPlugins`, `extraKnownMarketplaces` and `companyAnnouncements` are
      also read from `.claude/settings.json` and `.claude/settings.local.json`.
    - `config.json`: state the CLI manages itself, such as trusted folders (`trustedFolders`),
      signed-in accounts, installed plugins and marketplaces. Put settings in `settings.json`, not here.
    - `mcp-config.json`: your user-level MCP servers.
    - `copilot-instructions.md` and `instructions/*.instructions.md`: personal custom instructions.
    - `agents/`, `skills/`, `hooks/`: personal custom agents, skills and hooks.
    - `installed-plugins/`: installed plugins.
    - `session-state/<session-id>/`: one directory per local session, holding its event log (`events.jsonl`),
      metadata (`workspace.yaml`), plan (`plan.md`), session database (`session.db`), `checkpoints/` and `files/`.
      /session prune and /session delete remove sessions.
    - `session-store.db`: an index of local sessions used to search and list them.
    - `logs/`: process logs (`process-<timestamp>-<pid>.log`). Logs older than 7 days, and all but
      the newest 50, are deleted automatically. --log-dir writes logs to another directory.

  Downloaded CLI versions and other disposable data live in a separate cache directory, not in
  `$COPILOT_HOME`; see `COPILOT_CACHE_HOME` in `copilot help environment`.

  Custom instructions are also read from directories listed in `COPILOT_CUSTOM_INSTRUCTIONS_DIRS`, and from
  these files in the repository root and the current working directory:
    - `CLAUDE.md`
    - `GEMINI.md`
    - `AGENTS.md`
    - `.claude/rules/**/*.md`
    - `.github/instructions/**/*.instructions.md`
    - `.github/copilot-instructions.md`

Claude Code plugins, skills, hooks and settings:

  Copilot CLI reads much of a project's Claude Code configuration, so most of it works as it is.

  Plugins with a `.claude-plugin/plugin.json` manifest install with `copilot plugin install` or /plugin install,
  and a repository with `.claude-plugin/marketplace.json` is added with `copilot plugin marketplace add`.
  Plugin hooks also get `CLAUDE_PLUGIN_ROOT` and `CLAUDE_PLUGIN_DATA`.

  In a project, Copilot reads skills in `.claude/skills/`, agents in `.claude/agents/`, slash commands in
  `.claude/commands/`, and instructions in `CLAUDE.md`, `.claude/CLAUDE.md` and `.claude/rules/`.

  Hooks under Claude Code event names (`PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop`, `SessionStart`)
  run on the matching Copilot events, their tool matchers (`Bash`, `Read`, `Edit`, `Write`) match Copilot's
  tools, and their input uses Claude Code's field names (`session_id`, `tool_name`, `tool_input`) where other hooks
  get `sessionId`, `toolName` and `toolArgs`.

  A repository's `.claude/settings.json` and `.claude/settings.local.json` are read for hooks, `enabledPlugins`
  and `extraKnownMarketplaces`.

  Your personal `~/.claude/skills`, `~/.claude/agents` and `~/.claude/settings.json` are not read. Move personal
  skills to `~/.copilot/skills/` or `~/.agents/skills/` and agents to `~/.copilot/agents/`; personal
  instructions go in `~/.copilot/copilot-instructions.md`.
